# fitdash 0.9 polish implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close every known polish gap from the release so 0.9 is the last build before 1.0, which then carries only what real use finds.

**Architecture:** Small, independent fixes on top of `main` at `dbd36b3`. Pure logic stays in `metrics/` with JUnit tests first; UI changes reuse the existing components and `Palette`/`Type` tokens. Work on branch `polish-0.9`, merged to `main` at the end.

**Tech Stack:** Kotlin, Jetpack Compose, Material 3, WorkManager, Health Connect client, androidx core-splashscreen, kotlinx-coroutines, JUnit 4. No new dependencies.

**Spec:** No separate design document. The scope was agreed in conversation on 29 Oct 2026 and is the list below; the release spec `docs/superpowers/specs/2026-10-29-fitdash-release-design.md` still governs anything this plan does not change.

Scope, as agreed:
1. One "usual range" in the alert strip, notification and metric sheets.
2. Insights empty copy that is true when ten tags exist but no tag qualifies.
3. Skin temperature in the alert respects the Fahrenheit setting.
4. Journal file read and written off the main thread.
5. Splash follows the in-app theme on API 33 and above.
6. Chip rows keep their old height while tappable chips keep a 48 dp target.
7. Bedtime fallback uses whatever nights exist (three or more) instead of waiting for regularity to calibrate.
8. Nutrition entries saved without permission get written to Health Connect once permission is granted.
9. Drop the always-empty `weight_kg` column from the daily CSV.
10. Release notes with the migration lines, and a version bump to 0.9.

Added by the planner, for the user to confirm: a corrupt `journal.json` no longer crashes every launch (Task 3). It sits in the same code as item 4 and is the one known crash loop left.

## Global Constraints

- Verify every task with `JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home ./gradlew :app:testGithubDebugUnitTest :app:lintGithubDebug :app:assembleGithubDebug` (all pass, lint has no errors). Call this "the verification command". Tasks that touch flavour code or the manifest also run `:app:assemblePlayDebug`.
- Metrics code stays pure (no Android imports). Tests use `app/src/test/java/app/fitdash/Fixtures.kt` (`TODAY`, `IST`, `day`, `history`, `night`, `at`).
- Every colour goes through `Palette` or `LocalTheme.current`; no `Color(0xFF…)` in `ui/` outside `Themes.kt` and `Palette.Sun`.
- No new `_underscore` helpers, no small one-off helper functions, no docstrings, no comments that restate code. Copy is British English, sentence case, no emoji.
- Journal tags never go to Health Connect. The Play flavour never requests or writes nutrition.
- Commit after every task with the message given. No AI attribution trailer.

## Review Focus

1. **A tag toggled in the first moments after a cold start**, before the journal file has loaded, must land on top of the loaded journal, not replace it (Task 3 test).
2. **A corrupt or truncated `journal.json`** must not crash the app; the bad file is kept aside and the journal starts empty (Task 3 test).
3. **A nutrition entry that already has a Health Connect record id** must never be written again, and an entry whose retry fails stays as it was (Task 7 test).
4. **Naps and nights after the selected date** must not feed the bedtime fallback (Task 6 test).
5. **Any reading that triggers the morning alert** must sit outside the "usual" range the strip quotes, so the copy is never false (Task 1 test).
